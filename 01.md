## How is Python code executed? Explain Interpreted vs Compiled.

- Interpreted Languages (e.g., PHP, early Ruby): These languages traditionally use an Interpreter to read and execute the source code line-by-line at runtime. There is no pre-built binary. This makes debugging easier and the code highly portable, but it is significantly slower because the translation happens simultaneously with the execution.

- Compiled Languages (e.g., C, C++, Rust): In these languages, a Compiler translates the entire source code into machine-specific binary code before the program ever runs. This results in an executable file (like an .exe). Because the translation happens upfront, the execution is incredibly fast, but the code is "platform-dependent"—a program compiled for Windows will not run on macOS without being recompiled.

### Python’s Hybrid Execution Model

Python is technically an Interpreted Language, but it employs a "Compilation" step internally to boost efficiency. When you run a Python script, the process follows these distinct stages:

1. Compilation to Bytecode
When you trigger a script, the Python interpreter first parses your source code (.py) into an intermediate, platform-independent format called Bytecode. Bytecode is a lower-level, syntax-free representation of your logic, often stored in __pycache__ folders as .pyc files. Unlike machine code, bytecode is not understood by your CPU; it is understood only by the Python Virtual Machine (PVM).

2. The Python Virtual Machine (PVM)
The PVM is the heart of the Python runtime. It is a software loop that iterates through your bytecode instructions and maps them to the corresponding machine code instructions on your operating system. Because the PVM acts as a middleman, the same bytecode can run on Linux, Windows, or iOS without modification, provided a PVM is installed.

3. Internal Engine Behavior: The CPython Implementation
The most common version of Python is CPython (written in C). It manages memory through Reference Counting and a Garbage Collector. One notable quirk of CPython is the Global Interpreter Lock (GIL). The GIL is a mutex that allows only one thread to hold control of the Python interpreter at a time. This means that even on a multi-core processor, standard Python bytecode execution is effectively single-threaded, a historical design choice made to simplify memory management and C-extension integration.

### Summary of the Execution Flow:

Source Code: You write .py files.

Compiler: Python checks syntax and translates code into Bytecode.

Bytecode: Low-level instructions (e.g., LOAD_NAME, BINARY_ADD) stored in .pyc files.

Interpreter (PVM): The Virtual Machine reads bytecode and executes it on the host hardware.
