## Explain PEP 8 and why it matters.

### PEP

PEP stands for Python Enhancement Proposal. These are design documents providing information to the Python community or describing a new feature for Python. PEP 8, authored by Guido van Rossum (Python's creator) and others in 2001, is specifically the Style Guide for Python Code.

It covers everything from how many spaces to use for indentation to how you should name your variables. While the Python interpreter doesn't care if your code is "ugly" (as long as the syntax is valid), humans care deeply.

### Conventions

1. Indentation and Whitespace:

- The 4-Space Rule: Always use 4 spaces per indentation level. Never use tabs. While modern IDEs often convert tabs to spaces automatically, mixing them causes the dreaded TabError.

- Maximum Line Length: Limit all lines to a maximum of 79 characters. This allows developers to open two files side-by-side on a standard monitor without horizontal scrolling.

- Blank Lines: Use two blank lines around top-level functions and class definitions, and one blank line around methods inside a class.

2. Naming Conventions:

- Naming is one of the "hard problems" in computer science. PEP 8 provides a strict hierarchy to reduce cognitive load:

- Functions and Variables: Use snake_case (e.g., calculate_total_price).

- Classes: Use PascalCase or CapWords (e.g., UserAccount).

- Constants: Use ALL_CAPS (e.g., MAX_RETRIES).

- Packages and Modules: Use short, all-lowercase names.

3. Programming Recommendations:

- Imports: Imports should always be at the top of the file, grouped in the following order:

- Standard library imports.

- Related third-party imports.

- Local application/library-specific imports.

- String Quotes: Python treats ' and " the same, but PEP 8 suggests picking one and sticking to it consistently throughout a project.
