## Implement a script that accepts CLI arguments using `sys.argv`.

### Command-Line Interface (CLI) Arguments and `sys.argv`

In computer science, a **Command-Line Interface (CLI)** allows users to interact with a software program by providing text-based inputs directly to the operating system's shell. When a Python script is executed from the terminal, the shell passes the command and its accompanying arguments to the Python interpreter. The interpreter then populates a specific data structure to store these inputs, allowing the program to modify its behavior without changing the source code. This is fundamental for automation, scripting, and building professional developer tools.

---

### The `sys.argv` List

The `sys` module in Python provides access to variables and functions that interact strongly with the interpreter. The `argv` attribute (short for **Argument Vector**) is a standard Python **list** containing the command-line arguments passed to a script.

* **Structure**: The first element, `sys.argv[0]`, is always the **name of the script** itself (or the full path, depending on the OS). Subsequent elements (`sys.argv[1]`, `sys.argv[2]`, etc.) represent the arguments provided by the user, separated by spaces.

* **Data Type**: Every element in `sys.argv` is a **string**. If you pass a number (e.g., `python script.py 10`), Python will treat it as the string `"10"`. You must explicitly cast it to an `int` or `float` for mathematical operations.

* **Internal Mechanism**: When the CPython engine starts, it receives the `argc` (argument count) and `argv` (argument vector) from the C `main()` function. It then converts these C-style strings into Python string objects and packs them into the `sys.argv` list.

### Implementation: A CLI Calculator Script

Below is a robust implementation of a script that accepts a mathematical operation and two numbers as arguments.

```python
import sys

def main():
    ### 1. Concept: Validating Argument Length
    # We expect: script_name, operation, num1, num2 (Total 4)
    if len(sys.argv) != 4:
        print("Usage: python script.py <operation> <num1> <num2>")
        print("Example: python script.py add 10 20")
        sys.exit(1) # Exit with error code

    ### 2. Concept: Accessing and Casting Arguments
    # All inputs from sys.argv are strings by default
    script_name = sys.argv[0]
    operation = sys.argv[1].lower()
    
    try:
        num1 = float(sys.argv[2])
        num2 = float(sys.argv[3])
    except ValueError:
        print("Error: Arguments <num1> and <num2> must be numbers.")
        sys.exit(1)

    ### 3. Concept: Processing Logic
    if operation == "add":
        result = num1 + num2
    elif operation == "sub":
        result = num1 - num2
    elif operation == "mul":
        result = num1 * num2
    elif operation == "div":
        if num2 == 0:
            print("Error: Division by zero is undefined.")
            sys.exit(1)
        result = num1 / num2
    else:
        print(f"Error: Unknown operation '{operation}'")
        sys.exit(1)

    print(f"Executing {script_name}...")
    print(f"Result: {result}")

if __name__ == "__main__":
    main()

```

### Key Technical Considerations

* **Handling Spaces**: If an argument contains spaces (e.g., a file path like `C:\My Documents\file.txt`), the user must wrap the argument in **double quotes** in the terminal. Otherwise, `sys.argv` will split the path into multiple list items.
* **The Shell's Role**: The shell (Bash, Zsh, or PowerShell) performs **globbing** (expanding wildcards like `*`) before the arguments reach Python. If you run `python script.py *.txt`, `sys.argv` will contain a list of every `.txt` filename in the directory, not the literal string `"*.txt"`.
* **Limitations of `sys.argv**`: While `sys.argv` is excellent for simple scripts, it lacks built-in support for:
* **Named Flags** (e.g., `--verbose` or `-v`).
* **Help Menus** (automatically generated instructions).
* **Type Parsing** (it doesn't automatically convert strings to ints).


For complex applications, Python developers typically move from `sys.argv` to the `argparse` standard library or third-party tools like `Click`.
