## What are Docstrings? How do they differ from comments?

### Documentation Strings (Docstrings) in Python

In computer science, **Documentation Strings**, or **Docstrings**, are literal strings that occur as the first statement in a module, function, class, or method definition. Unlike standard code comments, docstrings are not ignored by the Python interpreter at runtime. Instead, they are parsed and attached to the object they describe as a specific attribute called `__doc__`. This makes the documentation **programmatically accessible**, allowing tools like IDEs, documentation generators (e.g., Sphinx), and the built-in `help()` function to display information about the code while it is running.

Docstrings follow the conventions laid out in **PEP 257**. They are typically enclosed in triple double quotes (`"""`), which allows them to span multiple lines, making them ideal for detailed technical explanations.

---

### Docstrings vs. Comments: Key Differences

While both serve to explain code, they operate at different levels of the software development lifecycle.

| Feature | Comments (`#`) | Docstrings (`"""`) |
| --- | --- | --- |
| **Primary Audience** | Developers reading the raw source code. | Users/Developers using the object or API. |
| **Visibility** | Stripped away/ignored by the interpreter. | Retained at runtime in the `__doc__` attribute. |
| **Location** | Anywhere in the code. | Must be the **first** statement in an object. |
| **Tool Integration** | Mostly ignored by documentation tools. | Primary source for `help()` and auto-docs. |
| **Scope** | Explains *how* or *why* a specific line works. | Explains *what* an object does and how to use it. |

---

### Internal Engine Behavior: The `__doc__` Attribute

When the CPython compiler encounters a string literal as the first statement of a function or class, it assigns that string to the object's memory structure. You can verify this using the `id()` and `type()` concepts we discussed earlier, or by simply accessing the attribute directly.

```python
def calculate_area(radius):
    """
    Calculate the area of a circle given its radius.
    
    Args:
        radius (float): The distance from the center to the edge.
        
    Returns:
        float: The total area calculated as pi * r^2.
    """
    import math
    return math.pi * (radius ** 2)

# Accessing documentation at runtime
print(calculate_area.__doc__)

```

If you were to use a comment `#` instead of the string literal, `calculate_area.__doc__` would return `None`, and the `help()` function would have no descriptive text to provide the user.

---

### Structure of a Professional Docstring

A "deep-dive" docstring usually consists of three parts:

1. **Summary Line**: A concise one-line description ending in a period.
2. **Elaboration**: A detailed paragraph explaining the behavior, edge cases, and internal logic.
3. **Metadata (Sections)**: Bulleted lists for Arguments (`Args`), Return values (`Returns`), and potential Errors (`Raises`).

### Historical Context and Quirks

* **Memory Usage**: Because docstrings are stored in memory as part of the function object, they do technically increase the memory footprint of a running program. In extreme memory-constrained environments, Python can be run with the `-OO` optimization flag, which strips docstrings to save RAM.

* **The "Stub" Docstring**: Even a simple `"..."` or `"Pass"` at the top of a function counts as a docstring.

* **Module-Level Docs**: If you place a triple-quoted string at the very top of a `.py` file (before any imports), it becomes the docstring for the entire module.
